# Бронирование помещений

Учебный проект по ООП, вариант 9. Написан на Java 21, собирается Maven, тесты на JUnit 5.

## Что умеет программа

Программа хранит помещения и брони и следит за тем, чтобы две брони одного помещения не пересекались по времени. Она умеет:

- бронировать помещение на заданный интервал времени (если помещение занято, выбрасывается исключение `BookingConflictException`);
- отменять бронь;
- показывать свободные окна помещения на выбранный день (рабочее время с 08:00 до 22:00);
- подбирать помещение по вместимости и времени;
- создавать повторяющиеся брони, например «каждый вторник до конца семестра»: занятые даты пропускаются, а в отчёте перечислено, что именно пропущено;
- переносить бронь в другое помещение или на другое время.

## Как устроена модель

Все классы лежат в пакете `booking`. Данные описаны в пакете `booking.model`, логика находится в пакете `booking.service`, а демонстрация работы — в классе `Main`.

Интервал времени описывает `TimeInterval`. Это `record` с началом и концом. Конструктор проверяет, что конец позже начала, поэтому некорректный интервал создать невозможно. Интервал считается полуоткрытым: начало входит в него, а конец нет. Благодаря этому брони с 10:00 до 11:00 и с 11:00 до 12:00 идут встык и не считаются пересекающимися.

Сотрудника описывает `Employee`, тоже `record`: табельный номер и фамилия.

Тип помещения задаёт перечисление `RoomType` (переговорная, лекционная аудитория, компьютерный класс, конференц-зал). У каждого значения есть поле с русским названием.

Помещение описывает класс `Room`: код, название, тип, вместимость и список оснащения. Два помещения считаются одним и тем же, если у них совпадает код, поэтому `equals` и `hashCode` написаны только по коду. Список оснащения копируется при создании помещения, и снаружи его изменить нельзя.

Бронь описывает абстрактный класс `Booking` с общими данными: номер, помещение, сотрудник и назначение. У него есть абстрактный метод `intervalOn(date)`, который возвращает интервал, занятый бронью в указанный день. Каждый вид брони реализует его по-своему, это и есть полиморфизм в проекте. Есть два вида броней: `OneTimeBooking` (разовая бронь на один интервал) и `WeeklyBooking` (повторяющаяся бронь раз в неделю, которая хранит список пропущенных дат и умеет составлять отчёт).

Вся логика собрана в классе `BookingSystem`. Он хранит помещения и брони, проверяет пересечения и рабочее время, умеет бронировать, отменять, переносить, считать свободные окна и подбирать помещения. Списки он наружу отдаёт только копиями, поэтому изменить его состояние можно лишь через его собственные методы.

## Исключения

`BookingConflictException` — проверяемое исключение. Занятое помещение является обычной ситуацией, а не ошибкой программиста, поэтому вызывающий код обязан её обработать. В демонстрации при конфликте программа показывает причину и предлагает другое свободное помещение.

Некорректные данные (конец интервала раньше начала, бронь вне рабочего времени, несуществующий номер брони) приводят к `IllegalArgumentException`.

## Запуск

Нужны JDK 21 и Maven.

Сборка проекта с запуском тестов и создание jar-файла:

    mvn clean package

Запуск демонстрации:

    java -jar target/room-booking-1.0.0.jar

Если в консоли Windows русский текст отображается некорректно, перед запуском выполните `chcp 65001`.

## Тесты

Запуск только тестов:

    mvn test

Тесты проверяют корректность интервалов, контракт `equals` и `hashCode` у помещения, копирование списка оснащения, обнаружение конфликтов, отмену броней, свободные окна, подбор помещений, повторяющиеся брони с пропуском занятых дат и перенос броней.
